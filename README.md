# ⚖️ 광고 문구 법률 검수기 (ad-law-checker)

병원·뷰티·건강기능식품·다이어트·커머스 셀러와 마케터가 상세페이지·블로그·스레드 글을
올리기 전에 **표시광고법·식품표시광고법·화장품법·의료법** 위험 표현을 1초 안에 확인하고,
안전한 대체 문구로 바꿀 수 있는 무서버 정적 웹앱입니다.

- 빌드 없음 · 서버 없음 · 계정 없음 · **본문 외부 전송 0건** (모든 검사는 브라우저에서)
- 입력과 설정은 `localStorage`에만 저장
- GitHub Pages 등 정적 호스팅에 그대로 올릴 수 있음 (`.nojekyll` 포함)

## 파일

```
index.html          화면 (4탭: 검수 / 대가성·고지 / AI 교정 / 검수 리포트)
styles.css          패밀리 룩 (IBM Plex Sans KR, 라이트/다크, 반응형)
data.js             규칙 50개 · 대가성 문구 6종 · 고지 체크리스트 8종 · 업종별 예시
core.js             검사 엔진 (겹침 병합, 안전도, 대가성 판정, 리포트, 프롬프트)
app.js              화면 조립·이벤트·저장
engines/ai-bridge.js  프롬프트 복사 + ChatGPT/Claude/Gemini 새 창 열기
test.js             단위 테스트 (node)
uitest.py           실제 Chrome 검증 · 미리보기 캡처 (playwright)
```

## 실행


## 핵심 기능

### 1. 업종별 4대 법규 원클릭 검수

| 업종 | 중심 법령 | 주로 잡는 표현 |
|---|---|---|
| 건강기능식품 | 식품 등의 표시·광고에 관한 법률 | 질병명·치료·완치, 의약품 대체, 인정 범위 초과 기능성, 체험기로 수치 개선 |
| 화장품·뷰티 | 화장품법 | 아토피·여드름 등 질환명, 세포 재생·콜라겐 증가, 시술 오인, 탈모·다이어트, 코스메슈티컬 |
| 병원·의료광고 | 의료법 | 치료효과 보장, 최상급·비교, 치료 후기, 비포·애프터, 수술 장면, 할인·소개비 |
| 커머스·체험단 | 표시·광고의 공정화에 관한 법률 | 근거 없는 1위·100%, 허위 할인, 비교·비방, 일반식품의 건강기능 표방, 청약철회 제한 |

최상급·비교·가격·인증 규칙은 `common`으로 묶여 **어느 업종에서나** 함께 검사합니다.

### 2. 위험 하이라이트 + 1클릭 치환

- **고위험(빨강)** 형사처벌·영업정지 조항이 걸리는 표현 · **주의(주황)** 근거·심의가 필요한 표현 · **권고(파랑)** 명칭·표시를 정확히 하면 되는 표현
- 카드마다 **법령 · 조문 · 제재 금액 · 사유 · 권장 문구**를 표시
- 권장 문구를 누르면 본문에서 그 자리만 교체, **되돌리기**(최대 40단계)로 원복
- 같은 구간에 여러 규칙이 걸리면 가장 위험한 규칙을 대표로 세우고 나머지는 `관련` 칩으로 보존
- "고위험 일괄 치환"으로 고위험만 한 번에 교체 후 문맥 확인

### 3. 대가성 문구 · 필수 고지

- 공정위 「추천·보증 등에 관한 표시·광고 심사지침」(2026.6.1 시행) 기준
- 본문에서 표시 위치를 판정: `표시됨 / 위치 미흡(본문 뒤·중간) / 불명확("체험단") / 없음`
- 받은 내용(제품·원고료·수수료·할인·직원·AI 가상 인물)을 고르면 지침 예시에 맞는 문구 생성 → **본문 맨 앞에 삽입**
- 매체별 위치 안내(블로그=제목/첫 부분, 인스타=첫 줄·사진 안, 유튜브=시작·끝 5분 반복)
- 필수 고지 체크리스트: 대가성, 출처·기준, 부작용·개인차, 의약품 아님 고지, 기능성 심사 범위, 사전심의, 청약철회, AI 인물

### 4. 내 구독 AI 교정 브리지

- 업종 + 걸린 표현 + 법적 근거 + 대가성 상태를 하나의 프롬프트로 생성
- 프롬프트 복사 후 ChatGPT / Claude / Gemini 새 창 (짧으면 `?q=`로 질문까지 전달)
- AI가 준 본문을 붙여넣으면 코드블록·머리말을 걷어내고 교체 → 자동 재검수 → **0건 통과** 확인
- 교체 전 본문으로 되돌리기

### 5. 클라이언트용 검수 리포트

- 근거·제재·권장 문구·대가성 상태·필수 고지·검수 한계가 담긴 텍스트 리포트
- 복사 / `.txt` 저장 / 인쇄(PDF)
- 프로젝트명·검수자 입력 반영

## 규칙 데이터 구조 (`data.js`)

```js
{
  id, industries: ['health' | 'beauty' | 'medical' | 'commerce' | 'common'],
  severity: 'high' | 'warn' | 'info',
  group, label,
  terms: [...] | regex + flags,
  onlyIfNear: [...], unlessNear: [...], unlessAfter: [...], nearWindow,
  law, ref, penalty, why, fixes: [...], evidence, probe
}
```

`probe`는 "이 규칙이 반드시 잡아야 하는 예시 문장"입니다. `test.js`가 모든 규칙에 대해
probe 검출 · 업종 격리 · 자기 예시 재검출(치환 후) · **다른 규칙 유발 여부**를 확인하므로,
동작하지 않거나 다른 규칙을 새로 부르는 대체 문구는 테스트에서 바로 실패합니다.

`unlessAfter: ['에 도움을 줄 수 있']`처럼 인정된 기능성 문구("체지방 감소에 도움을 줄 수 있음")는
통과시키고, 같은 단어라도 단정형("체지방 감소 효과가 있습니다")만 잡도록 조정했습니다.

## 한계 (화면과 리포트에 명시)

- 문구 **패턴** 대조입니다. 이미지·영상 속 글자, 음성, 전체 맥락, 실제 근거 자료의 진위는 보지 않습니다.
- 법률 자문이 아닙니다. 최종 판단은 변호사·공정위·식약처·의료광고심의위원회의 확인이 필요합니다.
- 사전심의 통과 여부나 인정(심사) 범위 일치 여부는 사람이 원문과 대조해야 합니다.
